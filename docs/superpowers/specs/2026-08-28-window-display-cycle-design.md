# Fn+Enter 窗口跨显示器循环设计

## 背景与目标

DockGesture 已经常驻菜单栏，并通过 Core Graphics 事件监听和 macOS 辅助功能权限处理全局鼠标手势。本功能在同一运行与权限体系中加入一个全局键盘快捷键：按下 `Fn + Enter` 时，将当前前台应用的聚焦普通窗口移动到下一台显示器。

目标是让跨屏移动足够可预测：每次只移动一个窗口，保持窗口尺寸与相对位置，在目标屏幕空间不足时安全收进可见区域，并在最后一台显示器后回到第一台。全屏、系统平铺窗口和不允许修改位置的窗口不在本期支持范围内。

## 用户体验

- 主键盘的 `Fn + Return` 与系统产生的 `Fn + Keypad Enter` 都视为同一快捷键。
- 每次完整按键只触发一次移动；长按产生的自动重复不重复移动。
- 匹配成功的按键按下与抬起事件都被拦截，前台应用不会额外收到回车。
- 显示器按 `NSScreen.screens` 当前返回顺序循环。该列表不缓存，每次触发都重新读取，以适应显示器连接、断开和重新排列。
- 快捷键跟随现有“启用 Dock 快捷控制”总开关。关闭后，鼠标手势、Dock 状态标记和跨屏快捷键一起停止。
- 成功或失败结果写入菜单栏的“最近操作”，不弹确认框或错误窗口。

## 范围

### 本期包含

- 全局识别 `Fn + Enter`。
- 获取前台应用的聚焦窗口。
- 在两台或更多非镜像显示器之间循环移动普通窗口。
- 保持窗口原尺寸与相对位置；目标屏幕不足时只缩小、不放大。
- 将最终窗口完整限制在目标显示器的 `visibleFrame` 内，避开菜单栏、Dock 和刘海安全区域。
- 对无窗口、单显示器、不可移动窗口和辅助功能调用失败给出菜单状态。
- 更新输入监控用途说明，明确包含键盘快捷键。

### 本期不包含

- 全屏窗口或系统平铺窗口跨屏移动。
- 退出全屏、移动后恢复全屏的动画流程。
- 私有 CGS、Spaces 或窗口服务器 API。
- 用户自定义快捷键、反向循环快捷键或按显示器名称选择目标。
- 移动同一应用的全部窗口。

## 方案比较

### 方案 A：扩展现有 Core Graphics 事件监听（采用）

在现有事件 tap 中增加键盘按下与抬起事件。它已经依赖输入监控权限，可以读取 `maskSecondaryFn`、虚拟键码和自动重复字段，也能拦截匹配事件，避免前台应用同时收到回车。该方案复用现有生命周期、总开关和错误恢复逻辑。

### 方案 B：AppKit 全局事件监控

实现简单，但全局监控只能观察事件，不能阻止事件继续投递。快捷键触发移动的同时可能在前台应用中插入一次回车，因此不采用。

### 方案 C：Carbon 全局热键

可以把热键注册与鼠标监听分离，但 API 较旧，Fn 修饰键与不同键盘上 Return/Keypad Enter 的兼容性不如直接读取 Core Graphics 事件。项目已经存在可用的事件 tap，因此不增加第二套全局输入机制。

## 架构

### `WindowMoveShortcutClassifier`（DockGestureCore）

纯逻辑组件，输入事件类型、虚拟键码、修饰键与自动重复标志，输出“忽略”“拦截但不触发”或“触发移动”。规则如下：

- 只接受 Return 或 Keypad Enter 虚拟键码。
- 必须包含 Fn；Command、Option、Control、Shift 任一存在时拒绝。
- Caps Lock、Numeric Pad 等非冲突标志不影响匹配。
- 首次 key-down 触发；自动重复 key-down 只拦截不触发。
- 首次匹配后记录对应键码，随后即使 key-up 时 Fn 已先松开，也拦截该 key-up 并清除状态。

### 全局事件监听

现有事件 tap 的事件掩码增加 `keyDown` 与 `keyUp`。鼠标事件继续走原有 Dock 手势路径，键盘事件交给快捷键分类器。分类器决定触发后，事件 tap 在主线程异步调用窗口移动控制器；回调中不执行辅助功能或显示器计算，避免阻塞系统输入事件线程。

### `FocusedWindowResolver`

通过 `NSWorkspace.shared.frontmostApplication` 获取前台进程，使用 `AXUIElementCreateApplication` 和 `kAXFocusedWindowAttribute` 获取聚焦窗口。它负责读取窗口位置、尺寸，以及检查位置和尺寸属性是否可设置。

如果没有前台应用、没有聚焦窗口、窗口位置不可设置，返回明确的失败原因。尺寸不可设置但原尺寸能完整放入目标 `visibleFrame` 时仍可移动；如果必须缩小而尺寸不可设置，则返回“不支持调整此窗口尺寸”。

### `DisplayCyclePlanner`（DockGestureCore）

纯逻辑组件，输入窗口矩形、显示器可见矩形列表，输出源显示器、下一显示器和目标窗口矩形。

源显示器以窗口和显示器可见区域的最大交叠面积确定；交叠面积相同时，以窗口中心所在的显示器优先，再以列表顺序决定。目标显示器是源显示器在当前列表中的下一项，最后一项循环回第一项。

### `FocusedWindowMover`

负责把 AppKit 的 `NSScreen.frame` 与 `visibleFrame` 转换为辅助功能使用的左上角全局坐标，先排除占满某台显示器完整 `frame` 的全屏窗口，再调用 `DisplayCyclePlanner`。普通窗口按“先尺寸、后位置”的顺序写回 AX 属性；如果不需要缩放，只写位置。每次写入都检查 `AXError` 并转换为用户可读结果。

## 窗口几何规则

设源可见区域为 `S`，目标可见区域为 `T`，原窗口为 `W`：

1. 目标宽高分别为 `min(W.width, T.width)` 与 `min(W.height, T.height)`，因此只在必要时缩小。
2. 在每个轴上计算窗口相对于源屏幕“可移动行程”的比例，而不是直接按绝对像素偏移：
   - `sourceTravel = max(0, sourceLength - originalWindowLength)`
   - `progress = clamp((windowOrigin - sourceOrigin) / sourceTravel, 0...1)`；行程为零时使用 `0.5`。
   - `targetTravel = max(0, targetLength - targetWindowLength)`
   - `targetOrigin = targetOrigin + progress * targetTravel`
3. 最终再次限制目标矩形，确保整个窗口位于 `T` 内。

这种计算在显示器尺寸和缩放比例不同的情况下仍能保持用户感知的相对位置。例如窗口在源屏右侧时，移动后仍处于目标屏右侧。

## 全屏与平铺处理

本期不尝试移动全屏或系统平铺窗口。窗口矩形与任一显示器完整 `frame` 在容差范围内一致时，按全屏窗口处理并直接停止；位置属性不可设置或写入位置返回不支持/无法完成时，按全屏、平铺或其他不可移动窗口处理。菜单显示“当前窗口不支持跨屏移动（可能处于全屏或平铺状态）”。不自动退出全屏，不拆散平铺组合，也不调用未公开的 AX 属性或私有 Space API。

## 状态与错误处理

- 少于两台可用显示器：`只有一台显示器，无需移动`。
- 没有聚焦窗口：`当前应用没有可移动的前台窗口`。
- 位置不可设置：`当前窗口不支持跨屏移动（可能处于全屏或平铺状态）`。
- 需要缩小但尺寸不可设置：`目标屏幕空间不足，且此窗口不允许调整尺寸`。
- AX 调用失败：显示包含阶段的简短结果，例如 `读取窗口位置失败` 或 `设置窗口位置失败`。
- 成功：`已将“窗口标题”移动到“显示器名称”`；窗口标题或显示器名称不可用时使用通用描述。

所有结果沿用现有 `lastAction` 菜单状态，不新增通知、弹窗或声音。

## 权限与隐私

不新增系统权限。辅助功能权限用于读取和修改其他应用的窗口；输入监控权限用于识别全局 `Fn + Enter`。`NSInputMonitoringUsageDescription` 更新为同时说明 Dock 鼠标手势与键盘快捷键。

## 测试

### 自动测试

- Return 与 Keypad Enter 在 Fn 按下时均匹配。
- 缺少 Fn 或带 Command、Option、Control、Shift 时不匹配。
- 自动重复 key-down 被拦截但不重复触发。
- Fn 先松开时，对应 key-up 仍被拦截并复位。
- 两屏和三屏循环，包括最后一屏回到第一屏。
- 窗口横跨两屏时按最大交叠面积选源屏。
- 同尺寸屏幕保持相对位置。
- 不同尺寸屏幕缩小超大窗口并完整限制在 `visibleFrame`。
- 无需缩小时保持原尺寸。
- 占满显示器完整 `frame` 的窗口被识别为全屏并拒绝移动。
- 原有 Dock 左键隐藏、Command+右键退出、Command+Option+右键强制退出测试全部继续通过。

### 实机测试

- 在当前两台显示器上连续按 `Fn + Enter`，窗口往返移动。
- 验证主键盘 Return 和键盘产生的 Keypad Enter 事件形态。
- 验证不同大小、贴边和跨屏窗口的位置保持。
- 验证 Finder、AppKit、Electron/Chromium 应用。
- 验证全屏窗口、无窗口应用和单显示器情况下的无破坏失败。
- 验证快捷键被拦截，文本编辑器中不会插入换行。
- 验证关闭总开关后快捷键完全失效。
