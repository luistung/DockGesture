# DockGesture 输入监控权限引导修正规格

日期：2026-08-13  
状态：设计已确认，等待书面规格复核

## 1. 问题

DockGesture 当前会调用 `CGRequestListenEventAccess()`，但 macOS 可能不会为输入监控权限显示可操作的系统提示。应用虽然在菜单中提供“打开输入监控设置”，首次使用者仍可能只看到笼统的“需要权限”，不知道应进入哪里、如何添加 DockGesture。

## 2. 目标行为

首次检测到缺少输入监控权限时：

1. 显示一次中文说明窗口；
2. 明确说明需要在“系统设置 → 隐私与安全性 → 输入监控”中启用 DockGesture；
3. 明确说明如果列表中没有 DockGesture，应点击“+”并从“应用程序”文件夹添加；
4. 提供主按钮“打开输入监控设置”和次按钮“稍后”；
5. 点击主按钮后直接打开输入监控设置页面。

自动权限轮询不得重复显示说明窗口。是否已显示只控制自动引导，不代表权限已授予。

## 3. 再次引导

用户从菜单选择“请求/重新检查权限”时：

- 仍缺少输入监控权限：再次显示输入监控说明，不受“首次已显示”状态限制；点击主按钮后打开对应设置页。
- 只缺少辅助功能权限：调用系统辅助功能授权提示，并打开辅助功能设置入口。
- 两项均已授予：不打开设置，将最近状态更新为“所需权限均已授予”。

“打开辅助功能设置”和“打开输入监控设置”两个直接菜单入口继续保留。

## 4. 状态显示

菜单栏状态必须按当前权限精确显示：

- `缺少辅助功能权限`
- `缺少输入监控权限`
- `缺少辅助功能和输入监控权限`

权限就绪时继续显示“运行中”；总开关关闭时继续显示“已暂停”。

## 5. 组件调整

- `PermissionStatus` 增加用于生成缺失权限状态和引导决策的纯逻辑属性。
- `PermissionController` 继续负责预检、系统请求与打开设置，不持有 UI。
- 新增或扩展权限引导协调逻辑，负责“首次只显示一次”和菜单手动触发可重复显示。
- `AppDelegate` 只在启动后的首次权限评估中触发自动说明；定时轮询只更新状态和启动/停止 event tap。
- 说明窗口使用 AppKit `NSAlert`，不新增独立窗口或复杂 onboarding。

## 6. 错误与边界

- 用户选择“稍后”时不自动打开设置，DockGesture 保持安全放行状态。
- 系统设置 URL 无法打开时，说明窗口仍保留完整手动路径，菜单状态继续显示缺少的权限。
- 用户授权后，现有两秒轮询自动恢复 event tap；如 macOS 要求重启应用，说明文字会提示退出并重新打开。
- 已经授予输入监控权限的用户不会看到该说明。
- 不改变 Dock 手势、登录项或应用退出策略。

## 7. 验证

自动检查覆盖：

- 缺少权限状态文案的三种组合；
- 首次缺少输入监控时需要自动引导；
- 自动轮询不会重复引导；
- 菜单手动触发可再次引导；
- 权限均已授予时不打开设置。

本机验证覆盖：

- 清除或关闭输入监控权限后首次启动可看到中文说明；
- 点击主按钮能到达输入监控设置页；
- 选择“稍后”不会打开设置且不会被轮询重复打扰；
- 菜单重新检查可再次显示说明；
- 授权后状态自动变成“运行中”。

本机交互验证需要用户本人操作系统权限，不由自动测试修改 TCC 数据库。
