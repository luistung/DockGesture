# DockGesture Dock 应用状态标记设计

日期：2026-08-26

开发分支：`feature/dock-state-indicators`

## 目标

在不改变 Dock 图标本体、点击区域或系统动画的前提下，用轻量视觉标记区分正在运行的 Dock 应用状态：

- 当前前台应用：图标右上角显示蓝色亮点。
- 已隐藏应用：图标右上角显示灰色圆形减号。
- 后台可见应用：保持原样。
- 未启动应用：保持原样。

Finder 与其他 Dock 应用使用相同规则。文件夹、废纸篓、分隔线、最小化窗口和没有 Dock 图标的后台进程不显示标记。

## 系统边界与方案选择

Apple 的公开 `NSDockTile` API 只能定制应用自己的 Dock tile，不能修改其他应用的 Dock 图标。因此本功能不写入 Dock 配置、不替换其他应用资源，也不使用私有 API。

采用鼠标穿透的透明覆盖层，在 Dock 图标右上角绘制状态标记。覆盖层只负责显示，不接受键盘或鼠标事件，不改变现有 Dock 手势的命中与执行流程。

未采用以下方案：

- 修改 Dock 数据库或应用图标文件：需要重启 Dock、不能实时变化，并可能破坏用户配置。
- 给所有运行应用显示三色标记：后台可见应用数量较多时视觉拥挤，且偏离“优先区分隐藏状态”的目标。
- 整体变暗隐藏应用图标：覆盖面积大，在 Dock 放大和自动隐藏动画中更容易暴露位置延迟。

## 状态规则

纯状态判定模块把同一个 Dock 图标对应的运行实例归并为一种显示状态，优先级如下：

1. 任一实例为当前前台应用：蓝色亮点。
2. 没有前台实例，但任一实例未隐藏：无标记。
3. 存在运行实例且全部隐藏：灰色减号。
4. 没有运行实例：无标记。

状态判定只依赖进程是否运行、`isActive` 与 `isHidden`，与窗口数量无关。应用关闭最后一个窗口但没有隐藏时仍属于“后台可见”，保持原样。

## 组件设计

### DockApplicationIndicatorState

位于 `DockGestureCore`，定义 `frontmost`、`hidden` 和 `none` 三种结果，并提供多实例优先级归并。该模块不依赖 AppKit，便于完整单元测试。

### DockApplicationStateMonitor

订阅 `NSWorkspace` 的应用启动、退出、激活、停用、隐藏和取消隐藏通知。每次通知后在主线程重新读取相关 `NSRunningApplication` 状态，并请求覆盖层立即刷新。

### DockItemSnapshotProvider

复用现有辅助功能访问方式，定位 Dock 进程并枚举 `AXApplicationDockItem`。每个快照包含：

- Dock 项目的屏幕矩形；
- 应用 URL、Bundle ID 与标题等匹配信息；
- 匹配到的运行应用实例。

匹配顺序沿用现有点击解析逻辑：应用 URL 与 Bundle ID 优先，标题仅作为唯一候选时的降级路径。无法可靠匹配时不显示标记。

### DockStateOverlayController

为标记所在屏幕维护透明、无边框、非激活且 `ignoresMouseEvents` 的覆盖窗口。窗口位于 Dock 上方，只绘制当前快照中的标记；没有标记时隐藏窗口。

覆盖层不会成为前台应用，不出现在 Dock 或应用切换器中，也不会改变底层 Dock 的左键、右键、拖拽、菜单和放大行为。

### DockStateIndicatorRenderer

根据 Dock 图标实际尺寸缩放标记：

- 前台亮点使用蓝色 `#38A9FF`，带深色描边和轻微外发光。
- 隐藏标记使用灰色 `#68717E` 圆底、白色减号和深色描边。
- 标记直径限制在 8–16 点之间，锚定图标右上角并随 Dock 放大同步移动。

## 刷新与坐标处理

应用状态通知触发即时重绘。Dock 位置还会因放大、自动隐藏、换边、屏幕切换或重启而变化，因此覆盖层使用自适应刷新：

- 鼠标靠近 Dock 或检测到 Dock 几何变化时，以最高 30 Hz 更新图标矩形。
- Dock 静止时降低刷新频率，减少辅助功能查询和 CPU 占用。
- 屏幕、Space 或 Dock 进程发生变化时立即丢弃旧快照并重新发现。

辅助功能坐标统一通过独立转换器映射到 AppKit 屏幕坐标，覆盖底部、左侧、右侧 Dock 以及不同原点的多显示器布局。

## 生命周期与开关

状态标记跟随现有“启用 Dock 手势”总开关：

- 启用且权限满足时启动监控和覆盖层。
- 暂停、退出或权限不足时立即移除全部覆盖窗口。
- DockGesture 自身不在 Dock 中，因此不会产生自标记。

不增加新的菜单项或额外权限。现有输入监控与辅助功能指引继续适用。

## 异常处理

- Dock 辅助功能树暂时不可读取：清空标记并在后续刷新中重试。
- Dock 自动隐藏且项目矩形不可用：隐藏覆盖层，Dock 再次出现时恢复。
- Dock 重启或 PID 改变：废弃旧 AX 元素并重新绑定。
- 多实例无法唯一对应具体 Dock 项目：按同 Bundle ID 聚合；无法安全聚合时不显示。
- 覆盖窗口创建或屏幕归属失败：只停用状态标记，不影响已有手势功能。

失败策略始终是“少显示标记”，不允许错误覆盖 Dock 图标或阻断系统交互。

## 测试与验收

自动化测试覆盖：

- 前台、后台可见、全部隐藏、未运行四种基本状态；
- 多实例状态优先级；
- Finder 与普通应用使用相同状态规则；
- 标记尺寸上下限与右上角锚点；
- 辅助功能坐标到 AppKit 坐标的单屏和多屏转换；
- 暂停、权限丢失或快照失败时清空标记。

手动验收覆盖：

- 隐藏、取消隐藏和切换前台时标记即时变化；
- Dock 位于底部、左侧和右侧；
- Dock 放大与自动隐藏；
- 多显示器、Space 切换、全屏应用和 Dock 重启；
- 标记窗口完全鼠标穿透，现有隐藏、退出、强制退出手势不回归；
- 静止时 CPU 占用无明显持续增长。
